# Documentation de Switch

Ces documents sont la mémoire du projet. Ils existent parce que le contexte
d'une conversation se perd et que le code, seul, dit *ce que* fait le produit
sans jamais dire *pourquoi* il le fait ainsi.

| Document | Ce qu'on y trouve |
|---|---|
| [01 — Le produit](01-produit.md) | Ce qu'est Switch, pour qui, et l'histoire des deux interfaces |
| [02 — La méthode encodée](02-methode.md) | Les portes, les critères, les preuves, le crédit de voix — la mécanique du diagnostic |
| [03 — Architecture](03-architecture.md) | Stack, routes, modules, données, routes IA |
| [04 — Décisions](04-decisions.md) | Les choix structurants et la raison de chacun |
| [05 — Migrations SQL](05-migrations.md) | Les migrations, dans l'ordre, avec leur statut |
| [06 — État et suites](06-etat-et-suites.md) | Ce qui n'a jamais été éprouvé, la dette connue, les pistes |

**À lire en premier si vous reprenez le projet :** [04 — Décisions](04-decisions.md).
C'est le document qui évite de défaire par ignorance ce qui a été fait exprès.

Ces fichiers se tiennent à jour au fil du travail — voir les instructions dans
`CLAUDE.md` à la racine.
